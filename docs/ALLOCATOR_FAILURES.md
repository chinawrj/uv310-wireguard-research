2026-10-26。用户已拿走设备，本轮仅运行 Cortex-M3 QEMU fixture，没有 USB、实机部署或网络压测。`rekey-memory/native.c` 未修改，仍为 SHA-256 `c970ff6a685817ae96c2bd2e04460a6a302bf50c8c6a29b234b479d3041835da`。新增测试明确刻画现有行为，不表示这些行为已经达到产品要求。

## “换钥”是协议机制，永久停止不是

WireGuard 定期通过握手生成新的会话密钥，配置中的长期身份私钥、公钥和 peer 不需要随之更换。这样为通信提供前向保密。官方实现的更新阈值为120秒，拒绝使用旧会话密钥的阈值为180秒；实际触发还与收发流量及握手角色有关，不能理解为闲置时无条件每120秒连接一次。新握手过程中可以继续用尚未过期的旧会话，正常实现不应每两分钟断网。[官方协议](https://www.wireguard.com/protocol/)；[官方常量](https://git.zx2c4.com/wireguard-linux/tree/drivers/net/wireguard/messages.h)。

本移植补充的是定时调度、握手状态和新旧会话衔接，并非自定义密码协议。它仍缺少完整的重试 jitter、接收触发的提前更新和服务端主动握手等行为。当前一次控制包分配失败就永久停止，是实验适配层的失败处理选择，**不是WireGuard协议要求**。

## 新增7项实验

| 场景 | 注入 | 观察结果 |
|---|---|---|
| ALLOC_NULL_FIRST | 首次握手控制包分配返回0 | `err=0xe4`、`stopped=1`、`phase=255`，未提交或释放不存在的包 |
| ALLOC_NULL_REKEY | 已有会话的更新控制包分配返回0 | 即便旧密钥仍有效也进入同一终止状态，外网IPv4转发停止 |
| ALLOC_NULL_KEEPALIVE | 保活控制包分配返回0 | 同样终止；因此此问题并不限于换钥 |
| ALLOC_BAD_LAYOUT | 分配成功，但packet refcount不符合布局要求 | raw释放一次、记账回到原值、`err=0xe5`终止，没有提交 |
| DEFERRED_RELEASE | submit返回，但暂不调用真实释放观察点 | 不重复分配；可处理响应、排队保活，待旧包释放后提交；无关/重复观察回调不误清ownership |
| HELD_RELEASE_EXPIRY | 已提交的包一直持有到旧会话过期 | 不复用仍归stock所有的包，过期后拒绝所测外网IPv4；释放后新握手和双向加密UDP恢复 |
| SUBMIT_NONZERO | 延迟释放，submit返回非零 | 保持所有权追踪到释放回调，不根据返回值自行释放或复用 |

前三项在恢复fixture分配能力后，继续推进8轮timer/worker/外网UDP，仍不会恢复。这确证**一次瞬时控制包分配失败可导致本轮实验永久断流**。不表示芯片永远不可恢复，也不是安全独立自启方案。检查的是选定客户端外网IPv4，LAN/DNS旁路与完整IPv6策略仍未解决。

SUBMIT_NONZERO只证明适配层对模拟返回值的处理；没有证明真实stock函数所有非零返回值的所有权语义。DEFERRED_RELEASE中的重复回调没有再次执行真实free，不能把它称作底层allocator能够容忍double-free。

## 证据与覆盖边界

运行：`make test`，依赖与工具路径见[BUILD.md](BUILD.md)。共32项场景、6项负向变异控制通过。新增变异分别删除分配失败关闭、删除畸形包释放、删除已有控制包的分配互斥，均被对应测试捕获。机器可读结果：[allocator-fault-tests.json](../outputs/uv310-wireguard/evidence/allocator-fault-tests.json)。原25项历史结果文件保留，不覆盖。

fixture独立跟踪包所有者、分配成功次数、raw释放、提交和内存记账。控制包按历史ABI计入580B payload及8B header；延迟释放期间保持占用，释放后检查回到基线。这个模型不是ROM allocator，不能测出真实碎片、OOM临界点、中断并发或heap峰值。合成测试仍绕过真实timer IPSR/ROM上下文校验；不产生UDP吞吐数据。

此前实机观察到allocation failure计数增至1，但未捕获足以把该次分配失败定位到本控制包路径的证据。此次结果不能给上次USB消失定因，更不能把“永久停止VPN”写成“设备重启/USB断开”。

## 下一候选改动的约束

优先评估**有退避、次数和队列期限限制的控制包分配重试**。此处是设计要求，尚未修改native实现：

1. 区分临时分配不足与ABI/元数据异常；后者继续终止，不能盲目重试损坏的packet。
2. 重试同一控制包分配时复用尚未过期的已生成消息，不重新握手消耗随机池、不重复加密或倒退发送counter。
3. 对每条控制消息限制尝试次数和最小间隔；保留原队列过期、密钥到期及实验总期限检查，不能靠重试延长旧密钥寿命。
4. 有效旧会话期间保持加密转发；无有效会话时拒绝所保护的外网流量。
5. submit后只能等待已验证的释放路径，不能用超时强行free stock仍持有的packet。
6. 覆盖首次握手/更新/保活、持续压力、容量恢复、32bit clock回绕、等待时密钥过期、实验期限到期，并保留本轮终止版本作为对照。

恢复硬件后仍须先核对身份、原厂镜像hash和网络基线，再用新实验材料完成最小实机对照。离线通过不授权复用旧keyed image。
