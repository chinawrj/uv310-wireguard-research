# ARM926 离线逆向：已拿到什么，下一步怎样验证

2026-10-28，用户要求并行研究 ARM926，评估在保留原厂联网功能的情况下运行自己的程序。三条独立分析线分别检查镜像完整性、启动/线程、数据/IPC。硬件仍由用户拿走，本轮没有 USB、设备网络、下载、刷写或运行态修改。

## 结论先行

**现有 AMSS ELF 的文件范围完整；整个 ARM926 启动与运行环境尚不完整。** 当前文件 1,880,064 字节，全部 13 个 program header 的文件范围均在其中；历史 3,672 次连续 sector 读取与独立前 64 KiB 捕获可交叉核对。AMSS 分区为 3,538,944 字节，尾部 1,658,880 字节未成功保存；早期整分区读取恰在 ELF 末端后的首个 sector 报错。不能把尾部称为确认空白，也不能把 ELF 文件称为完整 NAND 克隆。

这已经足够开展实质性的静态逆向。我们找到了正常启动、线程/回调和 USB ECM 包处理代码，ARM926 值得继续调查；还没有新的正常运行 Hello World、Wi-Fi 转发或 WireGuard 实测。

## 最重要的地址解释

ELF 的 `e_entry=0x100000` 对应 segment 2 的物理地址；该段虚拟地址为 `0xf0000000`。因此不能把文件偏移、启动物理地址和正常运行虚拟地址混用。主体还混合 ARM 与 Thumb，奇数函数指针通常涉及指令集状态；单纯把全部可执行段按同一种模式反汇编会产生伪代码。

带厂商高位 flags 的段需要单独分析。`memsz > filesz` 在这份镜像中尚不能一概解释为可自由使用的 BSS；装载、分页、压缩和运行态映射没有完全恢复。可解码、含字符串、ELF 标记可执行，都不等于某地址可安全调用。

## 自编程序的最小验证路线

现阶段目标是**与原厂共存的有界 Hello 回调**，不直接替换 AMSS，也不把 WireGuard 的长期计算塞进原厂未知预算的 worker。

1. **离线恢复正常调用条件。** 追踪应用初始化、worker 创建、提交函数、队列同步、满队列和 callback 返回约定；用原厂 callers 对照 ABI。
2. **建立装载与调用入口。** 需要正常运行状态下可验证的代码写入/装载与触发机制，确认执行权限、地址映射、缓存维护和恢复路径。下载模式已有 Hello World 不满足这一步。
3. **证明短时共存。** 硬件回来后，先读回版本/hash 并确认原厂 Wi-Fi/蜂窝正常；只执行一个有界回调，写入一个专用状态字段并返回。检查 worker 继续响应、Wi-Fi 与蜂窝保持工作。不先调用未确认的 printf、malloc 或文件函数。
4. **独立测资源。** 查明可用内存、栈、优先级、看门狗和 CPU 时间，再决定专用任务或分片执行。原厂队列只是候选启动机制，不能据此保证可承载密码计算。
5. **把 Wi-Fi 数据接进来。** 定位 DSP2 与 ARM 的真实包通道、双向交接、所有权、回压及蜂窝 UDP 出口。ECM 是 USB 数据路径证据，不能代替 Wi-Fi 数据路径。
6. **再移植 WireGuard。** 先单包双向测试，再握手、换钥、MTU、DNS、异常恢复、吞吐和长期运行。仍须解决随机数与跨启动新鲜度；主机引导只能解决其中部分准备工作。

这是研究/验收顺序，没有生成可刷写的 ARM 候选镜像，也没有把任何静态地址暴露为可直接从 USB 调用的通用命令。

## 什么情况下改变执行核选择

| 发现 | 对方案的影响 |
|---|---|
| 找到可恢复的 ARM 正常运行代码入口，并有稳定回调执行 | ARM 从静态候选升级为可实测候选 |
| ARM 有足够资源，但 Wi-Fi 数据不能直接到达 | 还要开发 DSP2↔ARM 桥；额外复制、IPC 延迟及恢复成本可能抵消收益 |
| ARM 可用资源/任务上下文不满足需要 | 不因 ARM 工具链方便而强行迁移 |
| ARM 能保留 stock 服务并完成双向 Wi-Fi/蜂窝链路 | 才能与已有 M3 路线做性能、稳定性和维护成本对比 |

M3 仍是已有正常 Wi-Fi 执行与短时 WireGuard 实机证据的主线；其资源与稳定性问题也仍未解决。DSP2 和 ARM926 是待验证的替代路线，不代表有空闲处理器可直接使用。

## “完全逆向”的边界

这轮交付可复核的镜像图谱和重点调用链，不宣称恢复原厂全部源码或全部行为。缺失 FSBL/OSBL、BootROM、完整 DSP1 与正常 ARM RAM 快照会限制跨阶段判断；当前硬件不可用，不能补采。即使完整获取这些字节，动态状态、硬件寄存器、跨核时序和真实资源预算仍需实机验证。

下轮从以上三份文档、对应 JSON 和精确镜像 hash 开始，优先缩小“正常代码入口”和“Wi-Fi 包能否进入 ARM”两个缺口，不重复只在下载状态执行 Hello World 的实验。
